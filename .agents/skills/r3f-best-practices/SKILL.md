# R3F Best Practices — Card Wars v3

Руководство по разработке 3D-сцены карточного стола на **React Three Fiber (R3F)**, **Three.js** и **@react-three/drei** в соответствии со спецификацией [docs/UI-3D.md](../../docs/UI-3D.md).

---

## 1. Главные правила производительности (Критично)

### ⛔ Никогда не вызывать `setState` внутри `useFrame`
- **Проблема:** `useFrame` вызывается каждый кадр (60–120 раз в секунду). Вызов `setState` приводит к постоянному ре-рендеру дерева React, уничтожая FPS и вызывая микрофризы.
- **Решение:** Анимации позиции, вращения, масштаба и материалов производить **исключительно через мутацию рефов** (`useRef`).

```tsx
// ❌ ПЛОХО: ре-рендер каждый кадр
const [rot, setRot] = useState(0);
useFrame((_, delta) => setRot(r => r + delta));

// ✅ ПРАВИЛЬНО: прямая мутация Three.js объекта через ref
const meshRef = useRef<THREE.Mesh>(null);
useFrame((_, delta) => {
  if (!meshRef.current) return;
  meshRef.current.rotation.y += delta;
});
```

### ⏱️ Умножение на `delta` (FPS-независимость)
Все непрерывные анимации и интерполяции обязаны умножаться на `delta` (секунды с предыдущего кадра), чтобы скорость была одинаковой на экранах 60 Гц, 120 Гц и 144 Гц:
```tsx
meshRef.current.position.x += speed * delta;
```

### 🔋 Режим рендера по требованию (`frameloop="demand"`)
В Card Wars сцена рендерится по требованию (экономия батареи и ресурсов, см. `UI-3D.md`):
- Когда сцена статична — кадры не рендерятся.
- При запуске анимации (полёт карты, поворот флюпа, падение жетона) или ручном вращении камеры вызывается `invalidate()`:

```tsx
const invalidate = useThree((state) => state.invalidate);

useEffect(() => {
  // При получении события анимации запрашиваем перерисовку
  invalidate();
}, [animatingEvent, invalidate]);
```

## 2. Оптимизация Raycasting и Pointer Events

На столе могут находиться десятки карт и сотни жетонов урона/мороза. Проверка пересечения луча мыши со всеми объектами сцены перегружает CPU.

- **Отключать Raycast на чисто визуальных объектах:** фоны, декоративные плоскости стола, неинтерактивные маркеры должны иметь `raycast={null}`:
```tsx
<mesh raycast={null} geometry={tableGeometry} material={tableMaterial} />
```
- **Слушатели событий только на интерактивных объектах:** вешать `onClick`, `onPointerOver`, `onPointerOut` только на саму карту или зону стола, но не на каждую цифру или под-элемент карты.
- Использовать `e.stopPropagation()` при клике на карту, чтобы клик не проваливался в лежащую под ней землю/стол.

## 3. Управление памятью и очистка ресурсов (WebGL Leak Prevention)

Утечки памяти WebGL приводят к падению контекста (`CONTEXT_LOST_WEBGL`), особенно на мобильных браузерах.

- **Очистка при размонтировании:** Геометрии и материалы, созданные императивно, обязаны очищаться в cleanup-функции `useEffect`:
```tsx
useEffect(() => {
  return () => {
    geometry.dispose();
    material.dispose();
  };
}, [geometry, material]);
```
- **Декларативные теги R3F:** Автоматически освобождают память при удалении компонента из дерева:
```tsx
<mesh>
  <boxGeometry args={[63, 89, 1.5]} />
  <meshStandardMaterial map={texture} />
</mesh>
```
- **Кэширование текстур:** Текстуры карт кэшируются по `cardId`. Не создавать новый экземпляр текстуры на каждый экземпляр карты одного и того же типа.

## 4. Архитектурная чистота сцены (Card Wars Domain Purity)

- **3D-компоненты не содержат игровой логики:**
  - Компоненты R3F **не решают**, законен ли ход.
  - Компоненты R3F **не мутируют состояние матча**.
  - Сцена принимает персональный снапшот (`viewFor(state, playerId)`) и отображает его декларативно.
- **Анимации управляются очередью событий:**
  - По событиям из протокола (`card_played`, `creature_flooped`, `damage_dealt`) проигрываются визуальные эффекты.
  - По окончании анимации позиция объекта совпадает с финальным снапшотом.

---

## 5. Инстансинг и процедурная геометрия

- Для множества одинаковых объектов (жетоны урона, жетоны мороза) использовать `InstancedMesh` или переиспользуемую геометрию `cylinderGeometry`.
- Избегать импорта тяжелых сторонних 3D-моделей: вся геометрия карт, земель и жетонов процедурная (скруглённые боксы, цилиндры, плоскости).

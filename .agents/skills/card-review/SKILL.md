# card-review — ревью кода Card Wars v3

Ревью по чеклисту проекта. Работает по свежему diff (git diff / PR / последний коммит); для больших объёмов — по файлам, указанным пользователем.

## Порядок работы

1. Прочитай diff. Для каждого пункта чеклиста ниже — поиск нарушений в изменённых файлах.
2. Спорные места читай в контексте: открой файл целиком, а не только строки diff.
3. Правила проекта — в `AGENTS.md` (кратко) и `docs/TECH.md` (полно). Если правило в AGENTS.md противоречит коду — фиксируй как нарушение; если противоречат друг другу документы — фиксируй как проблему документации.
4. Выдай отчёт в формате ниже. Не молчи о сомнениях: сомнительное место = отдельная строка с пометкой «вопрос».

## Чеклист

### Domain (packages/domain)
- [ ] Ноль I/O: нет fetch, fs, WebSocket, Date.now, Math.random — время и RNG только через порты (`deps`).
- [ ] Единственная зависимость — Immer. Нет импортов из presentation/adapters/protocol-валидации.
- [ ] **Нет хардкода карт**: ни id карт, ни названий, ни «если карта X, то…». Эффекты — данные + обработчики механик.
- [ ] Константы правил — из переданного config; нет чисел-дублей CONFIG.md (25, 40, 4 копии, 2 действия, 90 с, 60 с…).
- [ ] Переходы — чистые функции: `applyCommand(state, command, deps) → {state, events} | reject`.

### Скрытие информации (критично)
- [ ] Персональный вид строится только в `viewFor(state, playerId)`; нигде больше сериализация полного состояния.
- [ ] В любом JSON, уходящем клиенту, нет чужой руки/колоды (тест-проверка на утечку существует и обновлён).
- [ ] События не содержат скрытых данных; персональные события адресуются только получателю.

### Server (apps/server)
- [ ] Room (DO): write-through снапшота в storage после каждой применённой команды.
- [ ] Таймеры — стейт-машина в адаптере + alarms; domain получает только команду «время вышло».
- [ ] Боты применяют команды через тот же application-API, что и игроки.
- [ ] zod-валидация сообщений на границе (входящие и исходящие схемы protocol).

### Client (apps/client)
- [ ] UI тонкий: нет проверки законности ходов на клиенте (подсветка доступности — ок, это отображение).
- [ ] Снапшот — источник истины: клиент заменяет вид целиком; состояние не собирается из событий.
- [ ] Анимации — очередь по событиям, не мутируют состояние, не блокируют ввод данными.
- [ ] 3D-сцена — функция от снапшота; ничего игрового в компонентах R3F.

### Контент и документы
- [ ] Изменение правила игры → обновлён соответствующий документ (RULES / CONFIG / COMMANDS / UI / UI-3D / TECH) **до** кода; OPEN_QUESTIONS обработан.
- [ ] Новый параметр правил → сначала строка в `docs/CONFIG.md`.
- [ ] Каталог (`content`) корректен по формату `docs/CARDS.md`; тип земли радужная — `rainbow` (не `any` из старых данных).

### Общее
- [ ] Языки: идентификаторы/комментарии — en, строки интерфейса — ru.
- [ ] Тесты: изменения domain покрыты; RNG в тестах сидирован (детерминизм); нет скипнутых тестов.
- [ ] Чистота: нет закомментированного кода-мусора, отладочных console.log, TODO без ссылки на OPEN_QUESTIONS.

## Формат отчёта

```
Вердикт: OK / Есть замечания / Блокирующие нарушения

Блокирующие:
- [файл:строка] нарушение → какое правило → как исправить

Замечания:
- [файл:строка] … (серьёзность: high/medium/low)

Вопросы:
- [файл:строка] что неясно и почему
```

Блокирующее = нарушение конвенций из AGENTS.md (чистота domain, утечка информации, хардкод карт, дубли констант) или расхождение кода с документами без правки документов.

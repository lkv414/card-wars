# Карты и каталог

Этот документ описывает **единый формат данных карты** и подход к каталогу карт.
Визуальный формат карты (ячейки урона/хп/щита/бонусов) — в [UI.md](./UI.md), «Формат карты».

---

## Формат данных карты

Карта описывается **данными**; логика эффектов — отдельно (см. ARCHITECTURE.md, «Карты и эффекты»). Примеры JSON-карт (существо с пассивкой, платный флюп, строение с аурой) готовятся после завершения документации.

Поля (имена нейтральные, без привязки к языку/стеку):

| Поле            | Для каких карт | Содержание |
|-----------------|----------------|------------|
| `id`            | всех           | Уникальный идентификатор карты |
| `name`          | всех           | Название |
| `type`          | всех           | `creature` (существо) / `building` (строение) / `spell` (заклинание) / `companion` (парная) |
| `cost`          | всех           | Стоимость в действиях: 0, 1, … |
| `landType`      | всех           | Требуемый тип земли или `rainbow` (радужная — любой тип) |
| `attack`        | существ        | Базовая атака |
| `defense`       | существ        | Базовое хп |
| `image`         | всех           | Изображение для карты |
| `description`   | всех           | Игровой текст (нижняя часть карты) |
| `deckSet`       | всех           | Набор оригинальной игры, из которого карта |

### Структура способности

**Способности работают (механики v2).** У `CardData` есть поле `abilities: AbilitySpec[]`, у `HeroData` — `ability` и (для героев с вводом слова) `wordSetup`.

- Источник — `content/cards/mechanics/*.json` и `content/heroes/mechanics/*.json`; связка с картой **по `id`** (названия неуникальны). `tools/build-catalog.mjs` вливает способности в `packages/content/src/generated/cards.json` и `heroes.json`.
- Структурировано **837 из 853** карт (остальные — `flavorOnly` или нечитаемый OCR) и **25 из 74** героев; герои без способности играют как «ваниль».
- Каждая способность — либо декларативный `EffectSpec`, либо именованная механика (реестр в `packages/domain/src/mechanics`). Цели активной способности клиент собирает в одну команду; решения внутри триггеров идут через `pendingChoice`/`resolve_choice`. Дизайн: **[MECHANICS-V2.md](./MECHANICS-V2.md)**.
- Земли: `LandData` (44 скана в `content/lands/*.webp`) для выбора внешнего вида; играбельных типов — 7 (радужная земля в колоды не входит).

### Отдельные механики
- **Щит** — задаётся только способностью (пассивной или Флюпом), которая его даёт. Отдельного поля у карты нет.
- **Парная карта** — бонус направлен союзнику; работает только в режиме 2 на 2 (скрыта в редакторе колод по умолчанию). Активный бонус (Флюп) активирует владелец карты. В игре может находиться **только одна**; в колоде может быть несколько копий — для замены в процессе. Способности парных карт в текущем каталоге **не структурированы** (текст остаётся в `description`, как и у остальных карт до нового OCR): карта разыгрывается и заменяется как объект.

## Герои

Герой — **отдельная сущность**, не карта. Каждый игрок выбирает героя в редакторе колод перед партией.

Поля:

| Поле        | Содержание |
|-------------|------------|
| `id`        | Уникальный идентификатор |
| `name`      | Имя героя |
| `image`     | Изображение |
| `text`      | Формулировка способности для отображения |

Пример: герой **Бимо** — дополнительный бесплатный добор карты в начале хода (обычный бесплатный добор + ещё один от героя).

Каталог героев — `content/heroes/` (74 героя). Способность героя действует всю партию и обрабатывается доменом наравне со способностями карт (структурировано 25 героев, остальные — только текст).

## Каталог механик (ключевые слова способностей)

Собран из описаний карт оригинала — см. **[MECHANICS.md](./MECHANICS.md)**: триггеры (включая «ПРИЁМ» = флюп), операции, цели, условия и заметные закономерности (ауры строений «на этой линии», счётчики от сброса, состояния земель). Наполняется и уточняется новым OCR.

## Формат колоды

- Колода состоит из **40 карт**.
- **До 4 копий** одной карты. Лимиты копий задаются в **общем конфиге проекта** (по умолчанию — 4 для всех карт; точечные лимиты отдельных карт — переопределением, см. [CONFIG.md](./CONFIG.md)); каталог карт **вшит в игру** и не хранится в базе данных.
- Выбирается **тип земель** и настраивается их **расположение** (порядок типов земель в колоде). Сам порядок на правила не влияет — важен только для механик карт, ссылающихся на порядок / соседство земель.
- **Земли:** ровно **4 тайла**, тип каждого — любой из семи физических типов (`corn`, `blue`, `good`, `ice`, `sand`, `swamp`, `lava`; радужных земель в игре нет), **дубликаты разрешены**; выбор типа, арта и порядок — в редакторе колод.
- **Герой привязан к колоде** — колода = 40 карт + 4 тайла земель + герой + раскладка земель.

## Каталог карт

- **Источник контента** — карты **оригинальной настольной игры Card Wars** (наборы и expansions).
- **Каталог** — папка [`content/`](../content) в корне репозитория: `cards/` (853 карты; JSON и картинки `.webp` по подпапкам земель), `heroes/` (74 героя; JSON и картинки `.webp`), `lands/` (44 арта земель; JSON и картинки `.webp`), `index.json` (манифест всех записей с полем `kind`). Карта сама ссылается на свою картинку полем `image`.
- **Сборка каталога** для `@card-wars/content`: `pnpm --filter @card-wars/content generate` запускает `tools/build-catalog.mjs` и собирает `packages/content/src/generated/{cards,heroes,lands}.json` из `content/`; правки сгенерированных файлов вручную не делаются.
- Типы земель в колоде: `corn`, `blue`, `good`, `ice`, `sand`, `swamp`, `lava` (7 физических типов); `rainbow` используется как `landType` нейтральных карт и в эффектах.
- Способности структурированы в `content/*/mechanics/*.json` (837/853 карт, 25/74 героя); игровой текст остаётся в `description` для отображения.
- Каталог: 853 карты, 74 героя, 44 земли (всего 972 объекта). Историю OCR см. в [SWERKA-OCR-STATUS.md](./SWERKA-OCR-STATUS.md).

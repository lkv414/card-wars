# Механики v2 — проектный документ

Архитектура системы способностей карт, героев и парных карт. Принята после вырезания v1-системы эффектов (коммит `505c8f7`). Решения зафиксированы владельцем проекта 2026-11-02.

---

## Утверждённые решения

| # | Решение | Суть |
|---|---------|------|
| 1 | **Гибрид** | Простые способности — декларативные `EffectSpec` в JSON; сложные — именованные механики (код в domain), реестр без имён карт |
| 2 | **Связка по `id`** | mechanics-файлы ссылаются на карту/героя по `id` (названия неуникальны — 4 дубликата); название рядом — только подсказка |
| 3 | **Цели одной командой** | Все выборы активной способности клиент собирает заранее и шлёт одной командой; domain валидирует атомарно |
| 4 | **`pendingChoice` сразу** | Триггерные пассивки, требующие решения, ставят матч в ожидание ответа (см. §6) — часть каркаса M1 |
| 5 | **Герои = карты** | Единый `AbilitySpec` и единый пайплайн для карт, героев и парных карт; источник способности различается только `instanceId` |
| 6 | **Порядок внедрения** | Пачками по типам механик от простых к сложным (см. §9); герои не отдельный этап |

Цель: **пассивные способности работают сразу** (пересчёт в точке использования, без мутации состояния), **активные — как напечатано** (стоимость, цели, последовательность по описанию).

## 1. Единая модель способности

```ts
// packages/domain/src/mechanics/types.ts (черновик контракта)
export type Trigger =
  | 'on_cast' | 'on_enters_play' | 'on_death' | 'start_of_turn' | 'start_of_next_turn'
  | 'on_creature_attacks' | 'on_damage_dealt' | 'on_line_change'
  | 'on_flip' | 'on_draw' | 'on_spell_cast' | 'on_card_played'
  | 'start_of_battle_phase' | 'on_companion_event';
// on_cast — собственные эффекты заклинания, исполняются при розыгрыше;
// on_spell_cast — реакции ДРУГИХ карт на розыгрыш заклинания.

export interface AbilitySpec {
  kind: 'passive' | 'active';
  trigger?: Trigger;              // passive; active — триггера нет («ПРИЕМ» / кнопка героя)
  cost?: number;                   // active: действия, 0 = бесплатный
  additionalCost?: AdditionalCost; // «Сбрось карту…», «уничтожь существо под своим контролем…»
  oncePerTurn?: boolean;
  optional?: boolean;              // «можешь …»
  oncePerGame?: boolean;           // «В первый раз …»: одна активация за партию
  effect?: EffectSpec;             // вариант А: декларативная операция
  mechanic?: string;               // вариант Б: именованная механика + params
  params?: Record<string, JsonValue>;
  targets?: TargetSpec[];          // упорядоченные выборы игрока (см. §5)
  conditions?: ConditionSpec[];    // см. §7
  text: string;                    // формулировка для отображения
}
```

**Источник способности**: `EffectSource = { player: PlayerId; instanceId: string | null }` — у карт в игре `instanceId` заполнен, у героя всегда `null`. Диспетчер триггеров и скан модификаторов обходят единый список источников: карты всех игроков в игре + герой каждого игрока. Отдельной «системы героев» нет.

- `packages/content` отдаёт каталог с `abilities: AbilitySpec[]` у карт и `ability: AbilitySpec` у героев (поле возвращается после вырезания v1).
- Парные карты — те же `AbilitySpec`; триггер `on_companion_event` покрывает события партнёра (2v2).

## 2. Два класса пассивок

### А. Query-модификаторы — «работают сразу»

Не мутируют состояние; вычисляются сканом живых источников **в точке использования**. Условия (`while`) проверяются в момент запроса, поэтому замены, смерти и входы применяются автоматически.

| Модификатор | Точка запроса | Примеры |
|---|---|---|
| `stat_aura` | `computeEff` (бой, смерти, view) | Крепость Крови; Царь полей («за каждое…») |
| `cost_mod` | оплата стоимости в `play.ts` / `floop.ts` | Остролист (−2 действия) |
| `land_count_mod` | проверка требования земли | Ферма («считается за дополнительную землю») |
| `damage_redirect` | `dealToCreature` | Хлопковая Ведриния |
| `immunity`, `no_retaliation`, `suppress` (триггеры/активы линии) | `damage.ts`, `combat.ts`, диспетчер/флюп | Пушистая лиса; Призрачные бро; Дворец Костей; Чародейка Вайда |
| `suppress_triggers` | диспетчер триггеров (§3) | Дворец Костей |
| `grant_ability` | проверка наличия флюпа | Финн |

Функция-скан: `collectModifiers(draft, ctx, kind)` — перебирает источники, проверяет `conditions`, возвращает применимые модификаторы. Единая точка, кэш не нужен (поле ≤ 4×5 карт).

### Б. Триггерные пассивки

Центральный диспетчер `fireTrigger(draft, ctx, trigger, payload)` — единственный способ вызвать способности по событию. Точки вызова в движке:

| Файл | Триггеры |
|---|---|
| `match/play.ts` | `on_enters_play`, `on_spell_cast`, `on_card_played` |
| `match/combat.ts` | `on_creature_attacks` (до урона), `on_damage_dealt` (после каждого события урона) |
| `deaths.ts` | `on_death` (после удаления, внутри фиксцикла) |
| `match/turn.ts` | `start_of_turn`, `start_of_battle_phase` |
| `draw.ts` | `on_draw` |
| механики движения/флипа земель | `on_line_change`, `on_flip` |

**Порядок одновременных срабатываний** (детерминирован, фиксируется для реплеев): владелец-активный первым, далее по порядку посадки; внутри игрока — зоны слева направо, парная, герой последним. Триггер, порождённый способностью, обрабатывается после завершения текущей (очередь, не рекурсия; защита от бесконечных циклов — счётчик, как в фиксцикле смертей).

## 3. Гибрид: EffectSpec + именованные механики

- **EffectSpec** (~25 операций): `deal_damage` (существо/игрок, `pierce`, фильтр целей по земле зоны), `heal` (существо — снимает урон; игрок — до maxLives), `draw_cards` (величина/цель-игрок), `discard_top_deck`, `opponent_discards` (величина), `discard_from_hand` (выбор/случайно), `return_from_discard`, `destroy`, `move_creature`, `gain_actions`, `gain_shield`, `freeze_land` / `unfreeze_land` / `flip_land` (вверх/вниз), `stat_buff` (аура / навсегда / этот ход — turnBuffs, сгорают в конце хода), `destroy`, `move_creature` (назначение — выбор пустой зоны, своя/любая сторона), `freeze_land` / `unfreeze_land`, `reveal_deck_top`, `reorder_deck_top`, `play_for_free`, `put_card_from_hand_to_deck`, `win_if_opponents_deck_empty` (герой Билли), … — расширяется по мере разбора каталога; каждая операция документируется в [MECHANICS.md](./MECHANICS.md). Числа-параметры операций (`amount`, `count`) — тоже динамические величины, включая `per_counter` (счётчики хода: сыгранные заклинания, входы/смерти существ, смены линий; обнуляются в конце хода). Триггер `on_leave_play` срабатывает при уходе карты с поля любым путём (смерть, жертва, сброс, замена).
- **Модификаторы стоимости и земель** (сканируются в точке оплаты, docs/MECHANICS-V2.md §2А): `cost_mod` — `±N` к стоимости разыгрываемой карты (self-карта: Остролист −2 при условии, Домик из разного дерева −1 за каждое готовое существо); `land_count_mod` — «считается за дополнительную землю» (Ферма +1 corn).
- **Динамические величины** `StatAmount`: число | `{ per_discard: { every, amount } }` («за каждые 5 карт в сбросе») | `{ per_target: { target, amount, excludeSelf?, filter? } }` («за каждое применённое существо», «за каждую другую Бочку»); фильтры: `ready` (не флюпнутое), `landType`, `sameCard`.
- **TargetRef** пополняется `each_building_yours` (Нефтяная Вышка), `this_lane_own_creature` («твоё существо на этой линии», Школа), `this_lane_opponent_building` (Пес).
- **Подмена/снятие способностей (A6)**: `suppress` получает флаг `all` — «без текста»: скрываются актив, триггеры и пассивные модификаторы покрытого инстанса. Фильтр живёт в `forSource`: заглушённые инстансы не отдают ни способностей, ни модификаторов (ауры, cost-mod, триггеры — всё пересчитывается живьём). Выдаётся как обычный модификатор: `grant_modifier` (Пес — «пока применён», duration `while_flipped`) или через turnModifiers механикой. Механика **`grant_random_discard_active`** (Школа): существо своей линии теряет способности до конца хода и получает ПРИЁМ случайного существа с приёмом из своего сброса — в очередь turnModifiers кладутся suppress-all + `grant_ability` с выкатанным по RNG приёмом (duration `this_turn`); флюп-гейт при подавленных собственных способностях разрешает флюп выданной.
- **Именованные механики**: `packages/domain/src/mechanics/registry.ts` = `Record<string, MechanicHandler>`; сигнатура `(draft, ctx, source, params, choices, payload) => void` (`payload` — событие триггера, нужно механикам-реакциям вроде `copy_spell`). Файлы-пачки по этапам (`handlers.ts`, `handlers-h3.ts`, …), юнит-тест на механику, **никаких имён карт** в коде. (Решение владельца 2026-11-06: пачки файлов вместо «файла на механику» — так уже сделаны механики всех структурированных карт.) Реализованы: `chain_damage` (Убей-молния), `move_damage` (Отрази угрозу), `swap_lanes` (Скелет гастролер), `copy_spell` (Связь). Планируются: `replace_floop` (Школа), `reveal_until` (Остров голово-краба).
- **`copy_spell`** (реакция `on_spell_cast`): копирует заклинание из payload — кладёт в очередь триггеров его собственные `on_cast`-шаги от имени отвечающего игрока (`pendingFor: 'payload_partner'` → «другой партнёр»). Цели копии спрашиваются штатным pendingChoice-механизмом против `targets` скопированного заклинания (новая цель обязана быть легальна для копирующего). Копия бесплатна, не двигает карты и не увеличивает счётчики хода; исходник в сбросе — идентичность инстанса переиспользуется (для заклинаний это безопасно: `this_creature`-рефов у заклинаний нет).
- **Ледяные жетоны** (A7): `LandState.iceTokens`; ледяные земли входят в игру с одним жетоном (docs/RULES.md «Земли»). Операции `remove_token` / `transfer_token`; условие `while_lane_ice_token` (min — обе земли линии источника); `per_lands.token` («за каждую землю с жетоном»); фильтр `zoneToken` (существо стоит на земле с жетоном — ауры, урон). Событие `token_changed`.
- **Хвост ледяных карт (A7.1)**: `suppress` получает `attacks` («не могут атаковать» — гейт в цикле боя) и `filter` (покрытие по фильтру цели, напр. `zoneToken`); рефы `each_creature_of_choice_player` (Вафля) и `adjacent_own_land`; `per_lands.where: 'choice'` — земли игрока, выбранного в choice (Ледяная леди; `resolveStatAmount` получает choices); условия `while_own_turn` (Дворец Льда) и `while_no_tokens_in_play` (Полоса препятствий); величина `per_token_players` (Капитан мороженка); play-gate — условие `while_zone_ice_token` в способностях карты проверяется при розыгрыше (Ледяной душегуб, отказ `condition_not_met`); механика `token_bonus_damage` (базовый урон + бонус на жетонной земле — Замороженное сердце).
- **Ходы-состояния (A10)**: расходуемые скидки `grant_discount` { cardType, amount } — «следующее заклинание/существо в этот ход стоит на N меньше» (Призрак Джинни, Непустой гроб): `MatchState.discounts`, читаются в `playedCardCostModifier`, списываются при успешном розыгрыше, сгорают в конце хода. Запрет заклинаний `ban_spells_next_turn` (Дух ниндзя): `spellBansArmed` ставится по триггеру урона игроку, в startPlayerTurn превращается в активный бан на этот ход (`spellBansActive`), снимается в конце хода; отказ `spells_banned`.
- **Ауры на статы противника (A9)**: `stat_buff` получает `floorAttack` — «минимум 0» по АТК (Затопление −2, Аванпост попугаев −1, линия); работает и в аурах, и в this_turn-бафах (TurnBuff). Без явного «минимум 0» стат может уйти в минус — как напечатано (Мастер маскировки).
- **Боевой контекст защитника (A8)**: операция `defense_mod` — «+N АТК пока защищается» (Привидение, Духи): скан в точке расчёта сдачи в бою, бонус действует только на retaliation этого обмена; матчинг — по типу земли ЗОНЫ АТАКУЮЩЕГО (`landType`). Условие `while_own_card_in_play` { cardId } — «пока на поле есть своя карта X» (Малыш камнепух при своей Мамуле; перекрёстная ссылка на уровне данных, как TargetFilter.cardIds). Бонус не входит в `computeEff` — как и attack_mod атакующего, это боевой контекст.
- Способность использует **ровно одно**: `effect` или `mechanic+params` (валидация сборки).

## 4. Данные и сборка

```
content/cards/mechanics/<cardId>.json     { "cardId": "...", "name"?: "...", "abilities": [AbilitySpec...] }
content/heroes/mechanics/<heroId>.json    тот же формат
```

- `tools/build-catalog.mjs` читает обе папки и **вливает** `abilities` в генерируемые `cards.json` / `heroes.json`. Проверки сборки: `cardId`/`heroId` существуют; `name` совпадает с каталогом (warning); схема способности валидна; ровно один из `effect`/`mechanic`; дубликатов файла нет.
- **Отчёт покрытия** после генерации: X/544 карт и Y/25 героев со способностями + список карт, чей текст ещё не разобран (по пустому `abilities` при непустом `description`).
- Механики — публичная информация (напечатана на карте) и летят клиенту в составе каталога, как `description` сейчас.
- Правка текста OCR → правка mechanics-JSON, движок не трогается.

## 5. Таргетинг активных способностей

- Способность декларирует `targets: TargetAsk[]` — упорядоченный список требований (`own_creature`, `opponent_creature`, `any_creature`, `lane_creature`, `lane_opponent_creature`, `opponent_player`, `landscape`, `own_hand_card`); дополнительные стоимости (`discardFromHand`, `destroyOwnCreature`, `destroyOwnBuilding`) добавляют свои выборы **перед** объявленными. Статические цели (`this_creature`, `adjacent_creature`, `each_*`, `this_lane_*`) в список входов не входят.
- Клиент по `targets` рисует последовательный выбор («Цель 1/2…»), отправляет **одну** команду `floop`/`play_card` с `targets: TargetChoice[]` (позиция в массиве = позиция в `targets`).
- Domain валидирует весь набор **атомарно** до применения: каждый выбор против своего spec (тип, сторона, локация, легальность) → иначе отказ `target_required` / `invalid_choice`, состояние не меняется.
- `TargetChoice`-протокол расширяет текущий `CommandChoices`; zod — только в protocol-пакете.

**Сбор целей по одному (pending):** в триггере цели приходят **по одной** — на каждый `TargetAsk` отдельный `resolve_choice`. Команда валидирует собранный **префикс** набора (`ask[0..askIndex]` против `collected + ответ`), а не весь набор сразу: иначе первая же цель multi-ask способности отклонялась бы как неполная. Полная атомарная валидация действует для активов (`floop`/`hero_ability`), где цели приходят одной командой.

## 6. pendingChoice — ожидание решения внутри триггера

Для триггерных пассивок и опциональных эффектов («можешь…»), которым нужен выбор **вне команды игрока**:

1. Эффект заявляет потребность → переход состояния останавливается, матч сохраняет `pendingChoice: { playerId, reason, options | prompt, resume }` (ключ возобновления — сериализуемый дескриптор шага, без замыканий).
2. Сервер рассылает персональные виды: просящему — вопрос, остальным — факт ожидания.
3. Клиент отвечает новой командой `{ type: 'resolve_choice', answer }` (только в свой ход ожидания — или в любой, если событие чужое: уточняется при реализации).
4. Domain докатывает прерванный переход и продолжает очередь триггеров.

Механика очереди (M1-реализация): точки хуков не исполняют способности сразу, а кладут их в `ctx.frame.queue` (живёт в рамках одной команды); `drainTriggers` в конце батча (`afterEffects`, конец подготовки хода) исполняет очередь до пуста. Способность, требующая ввода (optional / targets у триггера), останавливает drain: остаток очереди сериализуется в `MatchState.pending` вместе со ссылкой на способность (`{player, instanceId, cardId, abilityIndex}` — данные перечитываются из каталога, состояние остаётся JSON-сериализуемым). Команда `resolve_choice` валидирует ответ, исполняет способность и продолжает drain. Пока `pending` активен, все команды кроме `resolve_choice`, `surrender` и `disconnect_loss` отклоняются (`choice_pending`). Активации «раз за ход» учитываются в `MatchState.abilityUses` (ключ `player:источник:индекс` → ход последнего использования).

Команды активации: `floop` (карта), `hero_ability` (способность героя), обе несут `targets: TargetChoice[]` и доп. стоимость; `resolve_choice` — ответ на ожидание.

Правила:
- **Таймер хода** продолжает идти; при истечении — детерминированный дефолт (скип опционального эффекта / автоприцел по правилу конкретной механики), партия не зависает (см. [NETWORK.md](./NETWORK.md)).
- Решение не отменяется игроком; перепроигрывание — только через сидированный RNG (детерминизм сохраняется).
- Скрытая информация: опции не содержат чужих скрытых карт; «посмотри N карт» отдаётся только через персональный вид владельца.
- Ограничение: `resume` — ограниченный набор точек возобновления (после каждой операции в effect-последовательности); механики с промежуточными решениями объявляют точки явно.

**Интерактивные цепочки (реализовано: Газы Огрa):** массив `effect` исполняется по порядку. Перед шагом движок считает, сколько выборов ему нужно (явные `TargetRef { kind: 'choice', index }` и неявные `discard_from_hand.count`); индексы соответствуют порядку `targets`, собранные выборы идут плотно по этому порядку. Если данных не хватает, переход ставит `pending.ask.kind = 'effect_step'`, сохраняет неисполненный хвост в `resumeEffects` и спрашивает ровно тот `TargetAsk`, который идёт следующим по порядку. Команда `resolve_choice` валидирует ответ, дописывает его в `collected` и докатывает хвост (для нескольких карточных выборов в одном шаге вопрос повторяется). Вскрытие карт (`reveal_deck_top`) остаётся публичным состоянием `MatchState.revealed`; персональный вид и снапшот содержат `revealed` для обеих сторон, пока окно не закрыто выбором или отменой по таймеру. Таймер отменяет способность и очищает окно без перемещения карт.

## 7. Условия

`ConditionSpec`: `if_discard_count`, `while_discard_count`, `while_undamaged` (scope `self`/`target`), `while_damage_exactly` / `while_damage_at_least` (scope `self`/`target`), `while_lane_empty_opponent`, `while_on_land_type`, `while_on_flipped_land` (Джейк), `while_distinct_lands` (min/max — Фиона, Присмо, Лимонное желе), `while_land_count` (min/max), `while_zone_has_building`, `while_empty_lands` (Лимонграб), `while_self_flipped` (Огненное торнадо), `while_opponents_hand_empty` (Митик), `while_no_other_creatures` (Одинокая панда), `if_payload_*` — условия по триггеру-событию (замена, тип вошедшей карты, «под твоим контролем», «другого», `if_payload_cost` — печатная стоимость карты события в [min..max]), `if_card_in_discard`, `while_turn_phase` — пополняется по каталогу. Payload `on_spell_cast`/`on_card_played` несёт стоимость карты события. Условия аур проверяются **по каждому кандидату-цели** (Мельница процветания, Марселин).

**Условия на уровне эффекта** (`EffectSpec.conditions`): `stat_buff` несёт собственные условия, которые проверяются per-target при каждом пересчёте статов — «пока на мне ровно 7 урона» (Мисс Пушинка), «если на этой земле строение» (Кукурузный чемпион). Условия способности (`AbilitySpec.conditions`) и условия эффекта — независимы: первые gate'ят всё умение, вторые — только этот бафф. Пересчёт живой: смена урона/строения переключает ауру без переигровки.

## 8. Скрытие информации и события

- События не содержат скрытых данных: «посмотрел колоду» — факт без содержимого; вскрытые карты (mill, reveal) становятся публичными и уходят в события с id карт.
- Вскрытая верхняя часть колоды (`reveal_deck_top`) хранится как публичное окно в состоянии матча и попадает в персональные виды обеих сторон до выбора/отмены; она не показывает остальную колоду и не переселяет карты сама по себе.
- **Приватные вскрытия** (`peek_deck_top`): окно `MatchState.peeks[player]` не попадает в события и в общие виды — только владелец видит его содержимое (`PlayerView.myPeek`). Событие `cards_revealed` — только для публичных вскрытий (mill, `reveal_until`): все события рассылаются всем игрокам комнаты, поэтому публиковать в них приватную информацию нельзя.
- Персональные виды (`viewFor`) остаются единственным источником скрытой информации; peek-эффекты отдают содержимое только владельцу.
- Журнал (RU-строки) пополняется по каждому новому типу события; клиентские анимации — только по событиям.

## Группа G1 — peek/поиск/игра из вскрытия

- **`reveal_until`** { max, match? { type?, landType?, cardIds? } }: вскрывает карты с верха своей колоды в публичное окно, пока не встретится подходящая (или max/конец колоды).
- **`play_revealed`** { destination? }: играет последнюю вскрытую карту бесплатно — существо/строение ставится в `destination` (реф или declared-ask `landscape`), заклинание читает свои `on_cast` (через очередь, с pending-опросами целей), компаньон занимает слот парного; остаток окна замешивается в колоду (RNG). Если окно пусто — только замешивание.
- **`resolve_revealed`**: `to: 'deck_top'` (выбранная — на верх колоды), `rest: 'deck'` (остальные остаются в колоде — переупорядочивание, Космическая сова).
- **AdditionalCost.floopOwnCreature** — «примени существо»: подготовка (флип) своего готового существа как доп. стоимость (Вырубка леса).

## Группа G2 — стоимость как величина, самопожертвование, счётчик сброса

- **AdditionalCost.destroySelf** — «Уничтожь [эту карту] >>>»: карта уничтожается после исполнения эффекта (Зеленая сирена, Пень с булавой).
- **Счётчик хода `cards_discarded`** — сбросы с руки всех игроков (Черный паладин).
- Механики: `discard_top_damage` (сброс верха колоды → урон всем существам = стоимость карты), `return_cost_actions` (вернуть существо в руку → действия = стоимости), `destroy_draw_cost` (уничтожить → каждый противник тянет = стоимости), `discard_then_damage` (противник сбрасывает N → урон = фактически сброшено), `mill_spell_discard` (сброс верха N, за каждое заклинание — сброс карты выбранным игроком).

## Группы G3–G7 — имена, бой, статусы, колода, ресурсы

- **G3**: `MatchState.turnPlayedCardIds` (все сыгранные за ход cardId) + величина `per_played_name` {matchers, amount} (Бизнес пес); `AdditionalCost.discardFromHandName` — сброс карты со словом в названии (Деревяшка).
- **G4**: `attack_mod.emptyLane` — бонус только при атаке пустой линии (hero_ice_king, в первый раз за ход — по счётчику `creature_attack`).
- **G5**: защиты `MatchState.protections` {instanceId}: атака по защищённому уходит в лицо, вражеский выбор цели отклоняется; снимаются в начале следующего хода владельца (Пещера одиночества). Громкий Бух: floop → `while_self_flipped` + механика `lane_or_face_damage` (существо линии или лицо). Условия `if_payload_zone_land_type` (Бриллиантовый Дэн), `while_own_card_in_play.minDamage` (кролик), `if_payload_cost` в реакциях входа (Храм солнца).
- **G6**: механика `swap_creatures` (обмен двух своих существ), фильтр `zoneBuilding` (Деревянный ритм), механика `damage_until_def` (Посох вуду), механика `splash_damage` (Взрывной мужик), cost_mod по счётчику входов (Замерянный голем).
- **G7**: `flavorOnly` в mechanics-файле — текст без механик засчитывается покрытием.

## Группа G9 — убийца, смерти по линии, min/max-таргетинг

- `MatchState.lastHits` — последний источник урона по каждому существу; в payload `on_death` попадают `killerInstanceId` и `cost` жертвы.
- Рефы `payload_killer`, `payload_player` (владелец жертвы), `min_attack_own` (существо с наименьшим АТК); величина `payload_cost`.
- Условия: `if_payload_killer_self`, `if_payload_zone_matches_self` (жертва на линии источника).
- Механики: `half_def_damage` (урон = половина макс. DEF, округляя вверх), `min_max_def_damage` (2 — наименьший DEF в игре, 1 — наибольший), `sacrifice_cost_damage` (уничтожить своё существо → урон всем существам противника = его стоимости, Сильная Сьюзан).

## Группа G10 — бесплатный розыгрыш с руки

- **`play_from_hand`** { target?, maxCost?, match?, destination? }: играет выбранную карту руки (ask `own_hand_card`) бесплатно при стоимости ≤ maxCost и совпадении с match; существо/строение — в `destination` (реф или ask `landscape`), заклинание — читает `on_cast`, компаньон — в слот. Неявный выбор карты руки учитывается в effectChoiceNeed (как у `discard_from_hand`).

## Группа G11 — игра из сброса

- **Ask'ы `own_discard_card` / `any_discard_card`**: выбор карты из своей стопки сброса либо из сброса любого игрока (`from: 'any'` — «твоего сброса или сброса противника», Последний шанс). Сброс публичен по правилам, поэтому отдельного скрытия не требуется.
- **`play_from_discard`** { target?, match?, from?, destination? }: выбранная карта покидает стопку сброса и входит в игру бесплатно — существо/строение в `destination`, заклинание читает `on_cast`, компаньон занимает слот. Карта из чужого сброса переходит под контроль владельца способности.
- **Фильтры ask'а** `cardType` / `maxCost` / `cardIds` ограничивают выбор на уровне валидации (Поднятие мертвых — «существо стоимостью 2 или менее»; Лунный урожай — «строение»). Домен отклоняет неподходящую карту до применения эффекта.
- **Явная ссылка `target`** на карту: порядок ask'ов и порядок `choice`-ссылок совпадают, поэтому в массиве эффектов карта берётся из конкретного ответа (`{ kind: 'choice', index: N }`), а не «первая карточная цель подряд».
- **Условия на уровне эффекта** (`EffectSpec.conditions`) — общий механизм для всех операций: шаг выполняется, только если его условия выполнены (Древний школяр: возврат Радужной карты безусловен, действие — только при строении на своей линии). Условия способности и условия эффекта независимы.
- **`remove_from_game`** { from, name }: удаляет из игры все карты с выбранным названием из стопки сброса выбранного игрока (Громила). Название берётся из публичной карты (ask `visible_card` — всё, что в игре или в любом сбросе); сбросы публичны по правилам, поэтому скрытия не возникает.
- **`move_creature.capture`** не используется: «Крок-зачинщик» перемещает существо противника на **его** сторону линии источника (реф `this_lane_opponent_land`) — контроль не меняется, зона назначения должна быть пустой.

## Группа G12 — выбор режима и передача карты

- **`heal_or_damage`** { target, mode, amount }: «Восстанови или нанеси N урона» — игрок выбирает режим (ask `heal_or_damage`, ответ `TargetChoice { kind: 'mode', mode: 'heal' | 'damage' }`), затем эффект лечит (снимает урон) или наносит урон выбранной цели. Режим — отдельный выбор в общем списке ask'ов, поэтому порядок `targets` и `choice`-ссылок остаётся единым.
- **`give_card`** { card, to }: передача карты из руки выбранному игроку («передай карту в руку своему партнёру» — Дай пять!). Карта меняет контроль на получателя.
- **`remove_from_game`** { from, name }: удаляет из игры все карты с выбранным названием из стопки сброса выбранного игрока (Громила). Название берётся из публичной карты (ask `visible_card` — всё, что в игре или в любом сбросе); сбросы публичны по правилам, поэтому скрытия не возникает.

## Группа H — примитивы финального бэклога

Contract decisions for the last 137 cards + 3 heroes (approved 2026-11-06). Text is interpreted **by intent** when the OCR is broken or contradicts RULES.md; every such interpretation is recorded here, not in code. Card names never appear in rule code — only in `content/*/mechanics/*.json`.

### H1. Новые виды ответа игрока

- `TargetAsk.kind: 'amount'` — числовой ввод. Поля `min`, `max`, `label` (RU-подпись для HUD). Ответ `TargetChoice { kind: 'amount', value }`, domain проверяет `min ≤ value ≤ max` и целочисленность. Используется для «нанеси 1 или 2 урона», «восстанови 1 или 2», «вылечи до 3 жизней».
- `TargetAsk.kind: 'choose_option'` — выбор одной из `options: string[]` («ИЛИ»-эффекты, выбор типа земли). Ответ `TargetChoice { kind: 'option', option }`. Старый `heal_or_damage` остаётся узким случаем и не удаляется.
- `TargetAsk.kind: 'damage_distribution'` — одним ответом `TargetChoice { kind: 'amounts', values: number[] }` игрок задаёт новый урон каждому существу из `among` операции `redistribute_damage`; domain проверяет сохранение суммы и запрет добивать (при `cap: 'defense'`).
- `StatAmount.kind: 'chosen_amount'` `{ index }` — величина берётся из `amount`-ответа с этим индексом. `StatAmount.kind: 'target_damage'` `{ target }` — текущий урон на цели. `StatAmount.kind: 'attached_count'` `{ target }` — число карт, положенных под инстанс.
- `ChoiceAnswerSchema.targets` и команды с `targets` принимают до **16** ответов (перераспределение урона по 4+ существам).

### H2. Операции

| Операция | Поля | Смысл |
|---|---|---|
| `redistribute_damage` | `among: TargetRef`, `amounts: number[]` (индексы `amount`-ответов), `cap?: 'defense' \| 'none'` | Сумма урона на выбранных существах сохраняется; игрок заново задаёт урон каждому. При `cap: 'defense'` значение не может достичь effective DEF (иначе существо погибло бы). Валидация: сумма новых значений == сумме старых. |
| `set_land_type` | `target: TargetRef`, `landType: LandType \| 'chosen'`, `until: 'next_own_turn'` | Земля теряет тип и получает выбранный до начала следующего хода владельца. |
| `swap_field_cards` | `a: TargetRef`, `b: TargetRef` | Обмен двух существ/строений местами (сохранение `flipped`, `damage`). |
| `attach_card` | `card: TargetRef`, `to: TargetRef`, `from: 'discard' \| 'field' \| 'death'` | Положить карту под инстанс (`CardInstance.attached: string[]`); при уходе носителя из игры вложенные карты уходят в сброс. |
| `repeat_effect` | `times: StatAmount`, `effect: EffectSpec` | Повторить шаг N раз (за каждое поле, за каждое существо), каждый раз со следующим `choice`-ответом. |
| `discard_chosen` | `card: TargetRef`, `from?: 'own_hand' \| 'any_hand'` | Сбросить конкретную карту (в т.ч. чужую, случайно выбранную в domain). |
| `pay_life` | `amount: number` | Заплатить жизнями (Рикардио) — дополнительная стоимость активной способности героя. |
| `ready_creature` | `target: TargetRef` | Подготовить существо (снять флип) — синоним `unflip`, оставлен для читаемости данных. |

- `stat_buff` получает `multiplier?: number` («АТК удваивается»): применяется в `computeEff` после сложения бонусов, до обрезки по `floorAttack`.
- `suppress` получает `spells?: boolean` и `creatureAbilities?: boolean`: «не может быть поврежден/выбран заклинаниями и способностями существ противника».

### H3. Условия, рефы и фильтры

- Условия: `while_effective_def_at_most { max, scope }` (осталось ≤ N DEF с учётом бонусов), `while_lives_at_least { min }`, `while_attached_at_least { min }`, `while_card_name_contains { word }` (для героя с выбранным словом), `while_played_card_type { type }` («сыграл не-кукурузные карты»), `while_no_spells_played`.
- `TargetRef`: `each_own_creature_damaged`, `each_creature_moved_this_turn`, `each_building`, `each_land`, `attached_cards`, `chosen_land_type`.
- `TargetFilter`: `movedThisTurn?: boolean`, `enteredThisTurn?: boolean` — отмечаются в `CardInstance` при перемещении/входе и сбрасываются в конце хода.
- `MatchState` получает `chosenWord?: Record<PlayerId, string>` (герой Колдунья-охотница), `CardInstance.attached?: string[]`, `CardInstance.movedThisTurn?: boolean`, `CardInstance.entersTapped?: boolean`, `CardInstance.noReady?: boolean`, `CardInstance.cannotReplace?: boolean`, `CardInstance.cannotReturnFromDiscard?: boolean`.

### H4. Интерпретации спорных текстов

- «Крысолов»: при атаке этим существом игрок может вместо него атаковать другим готовым существом под своим контролем; реализуется именованной механикой `replace_attacker` с `optional: true`.
- «Слинять»: выбранное существо покидает игру **перед** фазой боя, весь урон с него снимается; триггер `start_of_battle_phase`, `optional`.
- «Бесконечный комбайн»: урон себе равен **остатку effective DEF** выбранного существа, затем существо уничтожается (`mechanic: 'self_damage_then_destroy'`).
- «Перераспредели урон» (Заплатка, Вместе навсегда): сумма урона сохраняется; запрещено ставить значение, равное effective DEF или больше (иначе существо погибло бы), если текстом не оговорено иное.
- «Прозрачный ниндзя»: бросок d6 через сидированный RNG порта, на 4+ урон от атаки не проходит; заклинания и ПРИЁМЫ бросок не дают.
- «Муррризрак» / «Нельзя вернуть из сброса»: флаг `cannotReturnFromDiscard` проверяется всеми операциями возврата.
- 9 карт без игрового текста (Желтая сирена, Корова, Хэнклоп, Пони, Острая сосулька, Злое око, Филлис, Слюнявый чел, Овечка) — **осознанно пусто**: `flavorOnly: true`, `abilities: []`. Отчёт `generate` учитывает их отдельной категорией, а не как pending.

### H5. Батч H3 — флаги инстансов и именованные механики

- `set_instance_flag` { target, flag, value? } — выставляет `noReady`, `entersTapped` (заодно флипает карту), `cannotReplace`, `cannotReturnFromDiscard` на инстансе. `unflip` при `on_line_change` с условием `if_payload_instance_self` снимает флип только у носителя.
- `destroy_own_n` { count } — уничтожить N своих существ (в порядке зон) и добрать N карт; N приходит из `amount`-ответа (Милый Оверлорд).
- `StatAmount.target_attack` — эффективная атака цели без аур (база + бонусы + turnBuffs с множителем); `stat_buff.multiplier` теперь работает и для `this_turn`-бафов, не только для аур.
- Условия `while_target_moved_this_turn` (проверяется per-target при скане аур) и `if_payload_instance_self`.
- Именованные механики: `start_turn_move_or_discard` { fallback?: 'opponent_land' } (Тонущий клирик, Усталый вомбам, Предводитель Вайда), `enter_move_to_empty` { flipLand?: boolean } (поп-десанты), `self_damage_then_destroy` (Бесконечный комбайн), `steal_and_play_from_hand` (Башня правды).
- Интерпретации: «Нанеси 3 урона Щенку >>> +2 АТК» реализовано как активная способность с двумя шагами (урон по себе, затем баф) — урон наносится до бафа, что совпадает с напечатанным порядком. «Начало следующего хода» у Статичного поп-десанта — триггер `start_of_next_turn`, урон своему герою 1. «Укради случайную карту… и сыграй бесплатно» — карта берётся сидированным RNG из чужой руки, меняет контроллера и кладётся в первую свободную зону (заклинание уходит в сброс владельца способности).

### H7. Три последних героя (25/25)

- **Колдунья-охотница.** Новая команда `choose_word { player, word }` пишет слово в `MatchState.chosenWord[player]`; в персональном виде оно доступно только владельцу как `PlayerView.myWord`. Границы слова — **данные героя**: поле `wordSetup { min, max, label? }` в `content/heroes/mechanics/hero_huntress_wizard.json` (попадает в каталог при сборке). `choose_word` отклоняется, если герой игрока не имеет `wordSetup`, если слово уже выбрано или длина вне `[min..max]`. HUD читает те же данные каталога — имён героев в коде клиента нет. Способность героя — `on_card_played` с условиями `if_payload_player_self` + `if_payload_name_contains` и эффектом `deal_damage 1` по выбранному существу противника (`pendingChoice`).
- **Леди Ливнерог.** Новый триггер `on_return_to_hand` и счётчик хода `returned_to_hand` поднимаются в `return_to_owner` и `return_from_discard`. Условия `while_counter_at_least(min:2)` + `while_counter_at_most(max:2)` дают ровно одно восстановление 2 HP в ход — в момент второго возврата (осознанная трактовка «2 или более существ»).
- **Рикардио.** Активная способность героя `oncePerTurn` — декларативная цепочка `[pay_life 1 → peek_deck_top 1 → resolve_peek]` с ask `choose_option` (`keep` / `discard`). Приватное вскрытие (решение владельца 2026-11-07, замена утечной механики `reveal_maybe_discard`): `peek_deck_top` кладёт верхние N карт колоды актёра в **приватное окно** `MatchState.peeks[player]` — карты остаются в колоде, окно видно только владельцу (`PlayerView.myPeek`) и не порождает публичных событий. `resolve_peek` спрашивается ленивым `effect_step` (§6) уже **после** вскрытия: ответ `discard` убирает вскрытые карты из колоды в сброс (публичное событие `card_discarded`), ответ `keep` или отсутствие ответа — карты остаются в колоде. Окно очищается в обоих случаях, а также по таймеру и при отмене способности (`skipPending`).

# Структура проекта

Черновик организации кодовой базы. Технологии не фиксируются (см. README.md); здесь — слои, пакеты и правила зависимостей.

---

## Слои

| Слой          | Ответственность |
|---------------|-----------------|
| `domain`      | Правила, модели, state machine хода, эффекты, расчёт боя. Ноль внешних зависимостей. |
| `application` | Use-cases: начать матч, сыграть карту, флюп, «В бой», завершение по таймеру, ведение журнала. Оркестрирует domain, правил не содержит. |
| `presentation`| 3D-интерфейс: игра, лобби, редактор колод, главное меню. Отображает состояние, отправляет команды. |
| `adapters`    | Внешний мир: каталог карт и колоды (данные), сетевой транспорт, RNG, экспорт журнала в .txt. |

---

## Правила зависимостей

1. `domain` **не знает** ни об одном другом слое (ни UI, ни сеть, ни хранение).
2. `application` зависит только от `domain`.
3. `presentation` зависит от `application` — не обращается к domain напрямую.
4. `adapters` реализуют **порты** (интерфейсы), объявленные в `domain`/`application`, а не наоборот.
5. Игровое состояние существует в одном экземпляре-снимке; UI-состояние (открытые меню, выделения, анимации) живёт только в presentation и не смешивается с матчем.

---

## Ключевые контракты

### Команды
Действие игрока = команда: «сыграть карту», «флюпнуть», «добрать карту», «в бой», «поторопить», «муллиган». Domain проверяет законность и возвращает **новый снимок матча** или ошибку.

### События и журнал
Каждая применённая команда порождает **события** (сыграна карта, нанесён урон, существо уничтожено…). События:
- питают **журнал партии** (история ходов + экспорт .txt);
- питают presentation (анимации, подсветки) — UI реагирует на события, а не читает diff-ы снимков.

### RNG и время
Генерация случайных чисел и таймер передаются снаружи через порты — domain остаётся детерминированным и тестируемым. Таймер хода (90 секунд с ускорением) считает adapters/application; domain получает только команду «время вышло».

## Состав верхнего уровня (черновик)

```
docs/           — документация (источник правды)
domain/         — ядро правил + unit-тесты
application/    — use-cases, команды, журнал
adapters/       — каталог карт, колоды, сеть, RNG, экспорт журнала
presentation/   — главное меню, лобби, редактор колод, игровой экран (3D)
```

Точное разбиение на файлы и пакеты — при старте кода; фиксируется по мере реализации. Порядок работ — по [ARCHITECTURE.md](./ARCHITECTURE.md), «Эволюция»: domain + тесты → 3D-интерфейс → сохранения/реплеи → мультиплеер-адаптер.

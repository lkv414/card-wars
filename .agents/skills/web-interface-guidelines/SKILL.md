# Web Interface Guidelines — Card Wars v3

Руководство по верстке и UX для 2D-интерфейсов проекта Card Wars (DOM-экраны: меню, список комнат, лобби, редактор колод, модальные окна, настройки и HUD поверх 3D-сцены).

Основано на правилах [vercel-labs/web-interface-guidelines](https://github.com/vercel-labs/web-interface-guidelines).

---

## 1. Доступность (a11y) и управление фокусом

- **Полная поддержка клавиатуры:** Любая кнопка, селект, модалка и вкладка должны быть доступны по клавишам `Tab`, `Enter`, `Space`, `Escape`.
- **Видимое кольцо фокуса (`:focus-visible`):**
  - Не убирать `outline: none` без предоставления явной замены.
  - Использовать `:focus-visible` вместо `:focus`, чтобы клавиатурный фокус был заметен, но не мешал пользователям мыши.
- **Модальные окна и оверлеи:**
  - При открытии модального окна (диалог настроек, окно подтверждения, фильтр карт) фокус перемещается внутрь диалога.
  - Фокус «запирается» (focus trap) внутри диалога.
  - По нажатию `Escape` диалог закрывается, и фокус возвращается на элемент, вызвавший модалку.
- **Иконки без текста:** Любая кнопка, содержащая только иконку (например, закрытие окна `×`, кнопка настроек ⚙️), обязана иметь `aria-label="Описание"`.

## 2. Размеры интерактивных зон (Hit Targets) и мобильный UX

- **Минимальный размер кнопки/ссылки:**
  - На десктопе: не менее **24×24 px**.
  - На мобильных и сенсорных экранах: не менее **44×44 px**.
  - Если визуальный значок меньше 24 px, область нажатия расширяется через padding или псевдоэлемент `::before`/`::after`.
- **Шрифт в полях ввода:** `<input>` на мобильных устройствах должен иметь `font-size: 16px` (или больше), чтобы iOS Safari не увеличивал экран при фокусе (автозум).
- **Отключение задержки тапа:** Для мобильных устройств убирать дефолтный серый блик тапа `-webkit-tap-highlight-color: transparent`, обеспечивая кастомный активный стиль `:active`.

---

## 3. Стабильность верстки (No Layout Shifts) и асинхронные состояния

- **Скелетоны и резервирование места:**
  - Картинки карт и портреты героев загружаются асинхронно из каталога. Контейнер карты **всегда** должен иметь фиксированное соотношение сторон (63:89), чтобы верстка не прыгала при подгрузке WebP.
  - До загрузки картинки отображается процедурная canvas-заглушка или скелетон цвета типа земли.
- **Четыре обязательных состояния:** Любой асинхронный экран (список комнат, каталог карт, статистика) обязан обрабатывать:
  1. `Loading` — скелетон или ненавязчивый индикатор.
  2. `Empty` — понятное сообщение (например, «В этой категории нет заклинаний»).
  3. `Error` — текст ошибки с кнопкой «Повторить».
  4. `Success` — отображение контента.

## 4. Анимации и Motion Discipline

- **⛔ Запрет `transition: all`:**
  - Никогда не писать `transition: all 0.2s`.
  - Указывать только явно анимируемые свойства: `transition: transform 0.2s ease, opacity 0.2s ease`.
- **Поддержка `prefers-reduced-motion`:**
  - Уважать настройки системы пользователя:
  ```css
  @media (prefers-reduced-motion: reduce) {
    *, *::before, *::after {
      animation-duration: 0.01ms !important;
      transition-duration: 0.01ms !important;
    }
  }
  ```

---

## 5. Визуальная иерархия и контрастность

- **Контрастность текста:** Текст обязан соответствовать WCAG AA (контраст не менее 4.5:1 для обычного текста, 3:1 для крупных заголовков и бейджей).
- **Цвет не должен быть единственным индикатором:** Статус готовности игрока, фаза хода или перегрузка не должны обозначаться только цветом — обязательно дублировать текстом, бейджем или иконкой.
- **Главное действие (Primary Action):** На каждом экране должно быть одно визуально доминирующее главное действие (например, «В бой!», «Создать комнату»), а второстепенные («Отмена», «Назад») оформляются вторичными кнопками.
